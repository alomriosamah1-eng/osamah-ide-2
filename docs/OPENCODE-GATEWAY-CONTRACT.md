# عقد بوابة OpenCode المضمّنة

**الحالة:** المصدر الحقيقي مضمّن، وفحص الصحة وإنشاء جلسة تحققا محلياً. لا توجد دردشة نموذج نهائية أو نشر متحقق حتى الآن.

## مسار الاتصال المعتمد

لا تتصل واجهة React بخادم OpenCode مباشرةً، ولا تحفظ عنواناً محلياً أو بيانات اعتماد في `localStorage`. تستدعي الواجهة إجراءات tRPC في خادم Osamah؛ ويتحقق الوسيط من صحة المحرك ثم يمرر الطلب إلى OpenCode المضمّن على الحلقة المحلية `127.0.0.1:4096` فقط.

| الطبقة | المسؤولية | الحدود الأمنية |
|---|---|---|
| المتصفح | عرض حالة المحرك والنماذج المكتشفة والجلسات وطلبات الموافقة | لا يرى عنوان الحلقة المحلية ولا مفاتيح المزوّد |
| tRPC في Osamah | التحقق من المدخلات وتوحيد أخطاء البوابة | إجراءات الجلسات مغلقة افتراضياً |
| `server/opencode/api.ts` | تمرير HTTP إلى API الخاص بالمصدر المضمّن وتحويل النتائج | لا يختلق نموذجاً أو رسالة أو موافقة |
| `third_party/opencode/` | المصدر الأصلي غير المعدّل وواجهة API الفعلية | يبقى معزولاً عن تعديلات Osamah |

## الإجراءات المتاحة

تعرّض البوابة إجراءات قراءة للحالة والمصدر والنماذج، وإجراءات جلسة لإنشاء جلسة، وإرسال prompt، وانتظارها، وقراءة الرسائل، وجلب طلبات الموافقة، والرد عليها. يطابق تحويل الرسائل العقد المولّد في OpenCode: رسائل المستخدم تستعمل `text`، ورسائل المساعد تجمع أجزاء `content` ذات النوع `text`. كما يطابق تحويل الموافقات المسار `GET /api/permission/request` ثم يرشح البيانات بواسطة `sessionID` ويعرض `action` و`resources` فقط.

> لا يدّعي هذا العقد تدفقاً حياً عبر SSE بعد؛ المسار الحالي ينتظر اكتمال العملية ثم يجلب حالة الرسائل والموافقات.

## سياسة التنفيذ

لأن بوابة الحساب الحالية محلية في المتصفح وليست هوية صادرة من الخادم، فإن كل إجراءات `opencode.session.*` محمية حالياً بمتغير تشغيل صريح: `OPENCODE_EMBEDDED_EXECUTION_ENABLED=1`. عند غياب المتغير، تعيد البوابة `FORBIDDEN` ولا تنشئ جلسة ولا تنفذ أدوات. هذا حاجز مؤقت متعمد يقي النشر العام إلى أن تُربط الإجراءات بتفويض خادمي لكل مستخدم وجلسة.

إعداد مزوّد OpenCode ومفاتيحه يخصان وقت تشغيل OpenCode والخادم فقط. لا تضف مفتاحاً إلى واجهة React أو إلى `localStorage`، ولا تُنشأ أي قائمة بديلة إن أعادت `/api/model` قائمة فارغة.

## دليل تحقق المرحلة

شغّل `pnpm verify:opencode` فبدا المحرك المضمّن سليماً على `/api/health`. وشغّل `pnpm verify:opencode:session` فاستدعى `/api/model` وأنشأ جلسة حقيقية عبر `/api/session`. أعادت البيئة الحالية `modelCount: 0` لأنها لا تحتوي مزوّد OpenCode مهيأ؛ ولذلك لم يُرسل أي prompt ولم يُدّع رد نموذج أو مسار موافقة مكتمل.

## القيود والخطوة التالية

يجب قبل إعلان الدردشة التنفيذية تهيئة مزوّد حقيقي في OpenCode خارج الواجهة، وتشغيل البيئة بعلم تمكين التنفيذ في سياق محمي، ثم إثبات إرسال رسالة واسترجاع رد وعرض طلب موافقة والرد عليه. بعد ذلك يُستبدل أسلوب الانتظار/الجلب بربط SSE عند الحاجة. كما يجب التحقق من بناء ونشر الحاوية المخصصة قبل أي ادعاء بأن المحرك يعمل في نشر WebDev.

## مراجع المصدر المحلي

1. `third_party/opencode/packages/client/src/generated/client.ts` — المسارات الأصلية للجلسات والرسائل والموافقات.
2. `third_party/opencode/packages/client/src/generated/types.ts` — عقود `MessagesListOutput` و`PermissionsListRequestsOutput`.
3. `server/opencode/api.ts` و`server/opencode/router.ts` — الغلاف والحدود المملوكان لـOsamah.
