# قرار وقت تشغيل OpenCode الأساسي

**الحالة:** معتمد للتنفيذ المرحلي  
**النطاق:** Osamah IDE الحالي وملفات المصادر الأصلية الموجودة محلياً  
**تاريخ القرار:** 25 أغسطس 2026

## القرار

سيكون **OpenCode** وقت تشغيل الوكيل الأساسي في Osamah IDE. لا يعيد هذا القرار بناء OpenCode أو استبداله بطبقة محادثة مخصصة؛ بل يجعل OpenCode منفذ التخطيط واختيار الأدوات وتنفيذ العمليات، بينما يحافظ كل مشروع أصلي على منطقه الخلفي وخدماته وبياناته ضمن حدوده المستقلة.

لا توجد بيئة Cloud Computer في هذه المرحلة. لذلك يظل التنفيذ الحقيقي محصوراً في **نمط تشغيل محلي**: عملية OpenCode محلية وطبقة Gateway محلية قابلة للبدء من جهاز المطور أو من بيئة تشغيل دائمة تُضاف لاحقاً. لا يجوز للواجهة الثابتة الحالية الادعاء بأنها تنفذ OpenCode أو أن عملية أداة نجحت ما لم يصل إليها رد موثق من وقت التشغيل المحلي.

## الحدود المعمارية

| الطبقة | المسؤولية | ما لا تفعله |
|---|---|---|
| واجهة Osamah الحالية | اختيار النموذج، إرسال الرسالة، إظهار الحالة والنتيجة | لا تشغّل OpenCode داخل المتصفح ولا تعيد تنفيذ منطق الوكيل |
| OSAMAH Core Gateway | التحقق من السياق والصلاحيات، توجيه الطلب، ترجمة الأخطاء، بث الأحداث | لا يستبدل backends المشاريع الأصلية |
| OpenCode Runtime | تخطيط المهمة، اختيار الأدوات، تنفيذها والتحقق من نتائجها | لا يخترع نجاحات أو نتائج من دون مخرجات فعلية |
| Tool Registry وAdapters | تقديم واجهة مستقرة للأدوات الأصلية وربطها بعقود النواة | لا ينسخ Business Logic من المصادر |
| المشاريع الأصلية | تنفيذ الخدمات والـworkers والـMCP والتخزين وقواعد البيانات بحسب المشروع | لا تستورد تفاصيل مشاريع أخرى مباشرة |

## مسار التنفيذ المحلي المستهدف

```text
Agent Chat
   -> OSAMAH Core Gateway (محلي)
   -> OpenCode Runtime (محلي)
   -> OSAMAH Tool Registry
   -> Module Adapter
   -> Original Backend / Core
   -> Actual Result + audit event
   -> Agent Chat
```

اختيار النموذج في الدردشة يمثل الآن **تفضيل مهمة قابل للتمرير** (`providerID` و`modelID`). لا يتحول التفضيل إلى طلب شبكة أو تشغيل نموذج قبل أن يعلن Gateway حالة `ready` بعد فحص عملية OpenCode ومصدر النماذج.

## متطلبات الانتقال إلى التنفيذ الحقيقي

| الشرط | حالة المرحلة الحالية | معيار القبول |
|---|---|---|
| عقد جلسة OpenCode | قيد الإعداد | طلب محلي موثق يتضمن الرسالة والسياق وتفضيل النموذج |
| مصدر النماذج | قيد الإعداد | قائمة ديناميكية من وقت تشغيل OpenCode، لا قائمة متخيلة |
| Tool Registry | قيد التحليل | كل أداة تشير إلى Adapter وتنفيذ أصلي وSchema وصلاحية |
| تشغيل محلي | غير مفعّل بعد | health check يعيد حالة عملية OpenCode الحقيقية |
| أحداث وتدقيق | غير مفعّل بعد | كل تنفيذ يملك `runId` وحالة وخطأ قابلين للتتبع |

## قاعدة الصدق التشغيلي

> لا تعرض الواجهة حالة **متصل** أو **منفذ** أو **ناجح** إلا بعد أن يثبت Gateway نتيجة من عملية OpenCode أو من خدمة أصلية. في غياب وقت التشغيل المحلي، تكون الحالة الصحيحة هي **غير مهيأ محلياً**.

## الخطوة التالية

تنفيذ عقد Gateway المحلي وقارئ نماذج OpenCode مع واجهة حالة صريحة. بعد ذلك فقط يمكن استبدال قائمة النماذج الثابتة بقائمة حية وربط إرسال الرسائل بجلسة OpenCode حقيقية.
