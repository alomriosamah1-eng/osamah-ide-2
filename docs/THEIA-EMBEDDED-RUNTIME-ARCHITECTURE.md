# معمارية Theia المضمّنة

يحتوي المشروع الآن على لقطة غير معدّلة من مصدر **Eclipse Theia** في `third_party/theia`. تحفظ البيانات الوصفية في `third_party/THEIA-SOURCE.json` رابط المصدر والالتزام `a35c2a27e7d62cc83409f5996cbb076adc61d667` والرخصة المزدوجة والسياسة المتبعة للعزل.

| العنصر | القرار |
|---|---|
| مصدر Theia | لقطة أصلية من `eclipse-theia/theia` مع استبعاد `.git` و`node_modules` فقط |
| التخصيص | كل كود Osamah سيعيش خارج `third_party/theia`؛ لا تُعدل ملفات المورد |
| نقطة التشغيل المرجعية | مثال Theia المتصفحي هو تطبيق منفصل يحتاج بناء واعتماديات Node، لا مكتبة واجهة يمكن إدراجها مباشرة داخل Vite |
| النماذج والموفّرون | لا يعتمد الربط المقترح على أي موفّر أو نموذج؛ لن تستخدم مساحة البرمجة أمثلة Theia التي تضم إضافات AI |
| التعرّض للمتصفح | واجهة Osamah تتعامل مع حالة خادم مملوك لها؛ لا تُكشف أسرار أو عمليات نظام أو مسارات داخلية |

> «Theia is a framework to build IDEs, so you can't really run Theia itself. However, you can run the example applications included in its repository.» — وثائق Theia المحلية في `third_party/theia/doc/Developing.md`.

## حقائق التدقيق

المصدر المرجعي يتطلب Node.js 22 أو أحدث، ويضم مثال متصفح يبدأ عادةً خادماً مستقلاً. وتضم بعض أمثلة المورد إضافات ذكاء اصطناعي ومزوّدات لا تتوافق مع سياسة Osamah؛ لذلك سيبنى جسر تشغيل مملوك لـOsamah على الحد الأدنى من حزم IDE اللازمة، مع عدم تمرير أي إعداد مزوّد إلى المتصفح.

## التحقق التالي

الخطوة التالية هي اختيار حزمة تطبيق Theia متصفح قليلة الاعتماديات، ثم بناء غلاف خادمي محدود يتيح بدء التطبيق وفحص صحته في التطوير. لا يعني وجود المصدر المضمّن أن Theia يعمل بالفعل بعد؛ ستسجل الوثائق نتيجة بدء حقيقية فقط عند تحققها.

## نتيجة الربط الحالية

أضيف جسر Osamah الخادمي في `server/theia/embeddedRuntime.ts` وإجراءات قراءة في `server/theia/router.ts`. يميّز الجسر بين وجود المصدر ووجود ناتج التطبيق المبني وحالة خادم Theia، ولا يسمح ببدء عملية IDE من طلب متصفح. تتصل مساحة البرمجة بالإجراء `theia.status` وتعرض الحالة الفعلية مع زر لإعادة الفحص؛ لذلك لا تستبدل بطاقة الحالة محرر Theia الحقيقي أو تدعي أنه يعمل قبل بنائه.

أُثبتت الاستجابة الحية من خادم التطوير: أعاد `theia.status` الحالة `build-required` مع `sourceAvailable: true` و`applicationBuilt: false`، كما أعاد `theia.source` الحزمة `@theia/core` بالإصدار `1.74.0` والرخصة المعلنة. هذا يثبت رابط الواجهة/الخادم والمصدر، لا تشغيل بيئة IDE.

## قيد البناء الحالي

جُرّبت عملية تثبيت الاعتماديات الرسمية لبناء Theia. أصلحنا أولاً نقص مترجم C++ اللازم لمكوّن `native-keymap`، لكن التثبيت الكامل تعرض للإيقاف بضغط الذاكرة قبل اكتماله. أزيلت كل `node_modules` المولّدة من لقطة المورد بعد المحاولة، وعادت اللقطة إلى حجمها المصدرّي فقط. لهذا السبب يظل التشغيل الحقيقي لـTheia **غير متحقق**، ولن يبدأ الجسر أي عملية ما دامت نواتج `examples/browser-only/src-gen/backend/main.js` غير موجودة.

| طبقة الدمج | النتيجة | الدليل |
|---|---|---|
| لقطة المصدر والرخصة | مكتملة | `third_party/THEIA-SOURCE.json` |
| جسر الخادم وحالة التشغيل | مكتمل | اختبار `server/theia/embeddedRuntime.test.ts` وإجراء `theia.status` الحي |
| بطاقة مساحة البرمجة | مكتملة | `Programming` يستدعي `trpc.theia.status` و`trpc.theia.source` |
| بناء المثال المتصفحي وبدء Theia | غير مكتمل | التثبيت الكامل تجاوز حد الذاكرة؛ لا توجد نواتج بناء |

> لا يوجد هنا Cloud Computer أو نموذج محلي أو افتراض لمزوّد ذكاء اصطناعي. Theia إطار IDE؛ ويظل OpenCode منفصلاً عنه كمحرك جلسات الوكيل.
