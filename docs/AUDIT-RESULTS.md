# نتائج تدقيق Osamah IDE

## بوابة الحساب والهوية المحلية

| البند | الدليل | النتيجة |
|---|---|---|
| إنشاء الحساب | عقد `auth.local.register` وقاعدة `localAccounts` | لا يتطلب الاسم أو البريد؛ يقتصر على معرّف محطة محلي غير سري وكلمة مرور وسؤال وجواب الاسترداد. |
| الجلسة | `createLocalSession` وCookie من نوع HttpOnly | كلمة المرور والجلسة لا تحفظان في `localStorage`. |
| سؤال الاسترداد | `auth.local.recoveryQuestion` | يعرض سؤال الحساب المرتبط بالمحطة الحالية فقط. |
| تحقق الإجابة | `auth.local.verifyRecoveryAnswer` | **أُصلح أثناء التدقيق:** لم تعد الواجهة تنتقل إلى إعادة التعيين قبل نجاح تحقق خادمي للإجابة. |
| إعادة التعيين | `auth.local.resetPassword` | تعيد التحقق من الإجابة نفسها قبل تحديث كلمة المرور وإصدار جلسة جديدة. |

تم التحقق من هذا المسار عبر `pnpm check` و`pnpm test` و`pnpm verify:workspace-e2e`. يشمل الاختبار الطرفي رفض الإجابة الخاطئة وقبول الإجابة الصحيحة قبل متابعة عمليات مساحة العمل، ثم تنظيف البيانات التي أنشأها.

## مساحة البرمجة

| البند | الدليل | النتيجة |
|---|---|---|
| المشاريع | `workspace.project` و`workspaceProjects` | الإنشاء والفتح وإعادة التسمية والحذف مربوطة بعقود محمية ومقيدة بمالك المشروع. |
| الملفات والمجلدات | `workspace.file` و`workspaceFiles` | الإنشاء والحفظ وإعادة التسمية والحذف تتطلب ملكية المشروع أو العنصر؛ تطبيع المسار يتم في الخادم. |
| المهام والنشاط | `workspace.task` و`workspace.activity` | عمليات CRUD وحالة المهمة وسجل النشاط تحفظ خادمياً وتُعاد لمالك الحساب فقط. |
| عزل الحسابات | `verify-workspace-e2e.mjs` | **أُضيف أثناء التدقيق:** حساب محلي ثانٍ لا يرى مشروع الحساب الأول وتُرفض منه محاولة تعديل المشروع أو حفظ ملفه أو تحديث مهمته. |

تم التحقق عبر `pnpm check` و`pnpm verify:workspace-e2e`؛ ينشئ الاختبار موارد البرمجة، يثبت حفظها، يختبر عزلها بحساب ثانٍ، ثم ينظف موارد مساحة العمل.

## العروض والعقل الثاني ولوحة الوكيل والإعدادات

| البند | الدليل | النتيجة |
|---|---|---|
| العروض والشرائح | `presentations.*` و`PresentationStudio.tsx` | عمليات إنشاء العرض والشرائح وتحديثها وترتيبها وحذفها مربوطة بعقود محمية؛ لا تعرض واجهة العرض التوليد أو التصدير كمقدرة متاحة قبل تهيئة مزوّد Presenton. |
| عزل العروض | `verify-workspace-e2e.mjs` | **أُضيف أثناء التدقيق:** حساب محلي ثانٍ لا يستطيع تعديل عرض أو شريحة مملوكين لحساب آخر. |
| العقل الثاني | `secondBrain.*` ومحّول `extract_candidates_from_text` | عمليات الملاحظات والروابط والبحث واستخراج المهام تستخدم المسار الخادمي وملكية الطرفين؛ يمنع الخادم الرابط الذاتي والتكرار. |
| عزل العقل الثاني | `verify-workspace-e2e.mjs` | **أُضيف أثناء التدقيق:** حساب محلي ثانٍ لا يستطيع تعديل عنصر معرفة أو رابط مملوكين لحساب آخر. |
| لوحة OpenCode | `opencode.*` و`engines.status` | تعرض حالات المصادر والسياق المملوك للحساب فقط؛ لا تُمكّن الإرسال ما دام فحص OpenCode لا يكتشف مزوّداً أو نموذجاً مهيأً. |
| إعدادات الخادم | `preferences.*` و`ServerSettingsView.tsx` | اللغة والمظهر وتفضيلات الواجهة تحفظ خادمياً؛ حالات المصادر غير الجاهزة معروضة كحالة وليست كمفاتيح تفعيل وهمية. |
| بيانات الملف الشخصي الاختيارية | `buildProfilePatch` و`auth.local.updateProfile` | **أُصلح أثناء التدقيق:** لم تعد الواجهة تتطلب الاسم والبريد معاً؛ يمكن حفظ أحدهما بعد تشذيبه، ولا يصدر طلب تحديث فارغ. |

اجتازت هذه المرحلة `pnpm check` و`pnpm test` (**15 ملفاً / 29 اختباراً**) و`pnpm verify:workspace-e2e` و`pnpm verify:integration-boundary`. تؤكد النتيجة أن OmniRoute غير موجود في جذور وقت التشغيل، وأن بيانات الأقسام الثلاثة لا تعبر بين الحسابات في العمليات المختبرة.

## دليل تدقيق الواجهة والاتجاهات

| الفحص | الدليل | النتيجة |
|---|---|---|
| سطح المكتب 1440×900 | لقطة معاينة حية | تظهر مساحة العمل في الوسط، وشريط التنقل ولوحة الوكيل كمساحتين عموديتين منفصلتين، مع حالات المحركات الخادمية المعروضة بوضوح. |
| العرض 375×812 | لقطة معاينة حية | تنضغط مساحات العمل إلى تسلسل عمودي قابل للتمرير؛ تبقى عناصر التحكم الظاهرة ومؤشر حالة OpenCode متاحين. |
| العربية وRTL | لقطة المعاينة الحية | العربية هي لغة العرض الافتراضية، وتظهر تسمية التبديل إلى English في الشريط العلوي. لم يُسجَّل ادعاء بأن تبديل اللغة التفاعلي اختُبر يدوياً في هذه الجلسة. |

يثبت `OsamahWorkspace` ضبط `lang` و`dir` في جذر المستند عند تغيير اللغة، كما يحفظ التبديل عبر `preferences.update` الخادمي. تحققت بوابة HTTP الطرفية من إنشاء التفضيلات الافتراضية بالعربية/الداكن، ثم حفظ الإنجليزية/الفاتح، ومن تحديث الاسم منفرداً قبل مسار الاسم والبريد. اجتازت البوابات النهائية `pnpm check` و`pnpm test` (**16 ملف اختبار / 32 اختباراً**) و`pnpm verify:workspace-e2e` و`pnpm verify:integration-boundary`؛ ولم يجد فحص الحدود أي مرجع وقت تشغيل لـOmniRoute. بقي اختبار النقر اليدوي في جلسة المتصفح الحالية خارج هذه الجلسة؛ لذلك لا يثبت هذا السجل أكثر من اللقطات الحية واختبارات العقد والواجهة المنطقية المذكورة.
