# تشغيل اتصال Osamah IDE بخادم OpenCode المحلي

## الغرض

يوثق هذا الدليل الحد الأدنى لتشغيل اكتشاف النماذج من الواجهة. يربط Osamah IDE مع **OpenCode كأداة تشغيل مجانية** على جهاز المستخدم؛ ولا يتطلب Cloud Computer ولا يُنشئ أو يضبط نموذج LLM محلياً.

## خطوات الاتصال

1. شغّل خادم OpenCode على جهازك وفق وثائقه، ولاحظ المضيف والمنفذ الفعليين اللذين أعلنهما عند التشغيل.
2. أضف أصل واجهة Osamah IDE التي تفتحها في المتصفح إلى سماحية CORS ضمن إعداد OpenCode أو خيارات تشغيله.
3. في دردشة الوكيل، أدخل الأصل فقط بصيغة `http://127.0.0.1:PORT` أو عنوان حلقة محلية مسموح مماثل، ثم اختر **فحص**.
4. إذا أعاد `GET /api/health` الحالة `{ "healthy": true }`، تقرأ الواجهة `/api/provider` و`/api/model` وتعرض النماذج المفعّلة التي يكتشفها OpenCode حصراً.

## حل المشكلات

| ما يظهر في الواجهة | التفسير المحتمل | الإجراء |
|---|---|---|
| `OpenCode غير متاح` | الخادم لا يعمل أو لم يسمح بـ CORS | تحقق من تشغيل OpenCode ومن سماحية أصل الواجهة |
| `المحرك يحتاج مراجعة` | العنوان غير محلي أو الاستجابة ليست وفق العقد | استخدم أصل الحلقة المحلية فقط وتحقق من نسخة OpenCode |
| `OpenCode غير مهيأ` | لا توجد نماذج مفعّلة في OpenCode | هيئ مزوداً أو فعّل نموذجاً داخل OpenCode، ثم أعد الفحص |
| القائمة فارغة | لم يعلن OpenCode نموذجاً مفعّلاً صالحاً | لا تضف نموذجاً يدوياً؛ عالج التهيئة داخل OpenCode |

> حفظ العنوان في المتصفح لا يساوي تفويض تنفيذ. تبقى الرسائل غير مرسلة إلى أن تُختبر طبقة الجلسات والأحداث والموافقات مع OpenCode حقيقي.

## حالة التحقق لهذه المرحلة

تم فحص TypeScript للواجهة بنجاح، وفُحصت بوابة الحساب على الشاشتين المكتبية والجوالية. لا يعمل خادم OpenCode في بيئة تطوير المشروع الحالية؛ ولذلك لم يُسجّل اتصال أو نموذج مكتشف على أنه حقيقي. المسار المتاح الآن يتحقق من فشل الوصول صراحةً ويطلب تشغيل خادم OpenCode على جهاز المستخدم مع السماح لأصل الواجهة عبر CORS.
