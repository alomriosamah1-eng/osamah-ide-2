# خريطة تدقيق Osamah IDE

> **الغرض:** هذه خريطة عمل للتدقيق وليست وصفاً لقدرات مزعومة. كل حالة تشغيل أو رحلة مستخدم لا تُعد مكتملة إلا بعد وجود اختبار مناسب ودليل من التنفيذ الفعلي.

## 1. نقطة الدخول ومسار الواجهة

| الطبقة | الملف/المسار | المسؤولية | وضع التدقيق |
|---|---|---|---|
| التطبيق | `client/src/App.tsx` | مزوّد المظهر، حدود الخطأ، التوجيه | فحص مظهر، RTL/LTR، حدود الخطأ، ومسارات 404 |
| الصفحة الجذرية | `client/src/pages/Home.tsx` | الاختيار بين بوابة الحساب ومساحة العمل | فحص الانتقال بعد الجلسة والحالات غير المصرّح بها |
| الهوية المحلية | `client/src/components/AuthGate.tsx` | إنشاء الحساب والدخول والاسترداد | فحص الحقول والتحقق والأخطاء والجلسة |
| سطح المكتب | `client/src/components/OsamahWorkspace.tsx` | تنقل الأقسام، المشاريع، النشاط، ولوحة الوكيل | فحص كل تبويب وحالة التحميل/الخطأ والروابط الخادمية |
| العروض | `client/src/components/PresentationStudio.tsx` | تحرير العروض والشرائح | فحص CRUD، الترتيب، والملاحظات |
| الإعدادات | `client/src/components/ServerSettingsView.tsx` | التفضيلات وحالات التكامل الخادمية | فحص حفظ التفضيلات والإفصاح عن حالة المحركات |

يوجد مساران عامان فقط في تطبيق Wouter: `/` و`/404`. لذلك تقع رحلة المنتج كاملة داخل الصفحة الجذرية، ويجب تدقيق الانتقال بين بوابة الحساب ومساحة العمل من خلال حالة الجلسة الخادمية لا عبر حالة واجهة محلية فقط.

## 2. واجهة العقود الخادمية

| نطاق tRPC | الجسر الخادمي | بياناته أو مصدره | نقاط التدقيق الأولية |
|---|---|---|---|
| `auth.local` | `server/routers.ts` و`server/localAuth.ts` | `users` و`localAccounts` وCookie جلسة HttpOnly | منع إعادة التسجيل لنفس معرّف المتصفح، التحقق من كلمة المرور والاسترداد، الخروج |
| `preferences` | `server/preferences/*` | `userPreferences` | ملكية المستخدم، القيم المسموحة، وتطبيق العربية/المظهر |
| `workspace` | `server/workspace/*` | المشاريع والملفات والمهام والنشاط | الملكية، العمليات الذرية، المسارات المتكررة، النشاط |
| `secondBrain` | `server/secondbrain/*` | عناصر وروابط المعرفة واستخراج المهام | الملكية الثنائية للرابط، منع الرابط الذاتي والتكرار، البحث |
| `presentations` | `server/presentations/*` | العروض والشرائح والنشاط | ملكية العرض، ترتيب الشرائح، الحذف المتسلسل |
| `opencode` | `server/opencode/*` | مصدر OpenCode وجلسة المحرك | عدم تمكين الإرسال بلا نموذج مكتشف ومزوّد خادمي |
| `theia` | `server/theia/*` | مصدر Theia وحالة نواتج المثال | عدم ادعاء تشغيل المتصفح بلا artifact صالح |
| `presenton` | `server/presenton/*` | مصدر Presenton وفحص FastAPI المحلي | عدم ادعاء التوليد أو التصدير بلا مزوّد مفعل |
| `engines` | `server/engines/router.ts` | حالات الجسور والسياق المملوك للمستخدم | عدم تسريب سياق مستخدم، اتساق حالة الواجهة مع المصدر |

## 3. نموذج البيانات والعلاقات المطلوبة للمراجعة

| الكيان | الملكية/العلاقة | عمليات التدقيق الحرجة |
|---|---|---|
| `users` | الجذر لكل بيانات المستخدم | جلسة صحيحة، معلومات ملف اختيارية، وحذف متسلسل |
| `localAccounts` | واحد لواحد مع المستخدم | معرّف متصفح عشوائي فريد، hashes فقط لكلمة المرور وإجابة الاسترداد |
| `userPreferences` | واحد لواحد مع المستخدم | إنشاء افتراضي، تحديث مقيد بالقيم المسجلة |
| `projects` → `projectFiles` | مشروع مملوك ثم ملفات تابعة | عزل ملكية المشروع، مسار ملف فريد لكل مشروع، منع تعدي المستخدمين |
| `tasks` | مملوكة للمستخدم وقد ترتبط بمشروع | انتقال الحالة والتاريخ وربط مشروع يملكه المستخدم |
| `knowledgeItems` → `knowledgeLinks` | عناصر معرفة وروابط مملوكة | تحقق ملكية طرفي الرابط، منع التكرار والربط الذاتي |
| `presentations` → `presentationSlides` | عرض مملوك وشرائح تابعة | ترتيب فريد، حذف متسلسل، عدم تعديل عرض غير مملوك |
| `activityLog` | مملوك للمستخدم | تسجيل عمليات حقيقية فقط وعدم استعماله كبيانات تجريبية |

## 4. مصادر الطرف الثالث وحدود التشغيل

| المصدر المعتمد | موضع المصدر | الجسر | الدليل الحالي | شرط الانتقال إلى «تشغيل فعلي» |
|---|---|---|---|---|
| OpenCode | `third_party/opencode` | `server/opencode/*` | Bun والجلسة الأصلية قابلان للفحص؛ لا نموذج مكتشف | تهيئة مزوّد مرخّص خادمياً ثم اختبار إرسال/رد/موافقة |
| Eclipse Theia | `third_party/theia` | `server/theia/*` | المصدر موجود؛ محاولة اعتماديات المثال توقفت تحت ضغط الذاكرة | بيئة بذاكرة كافية وبناء artifact متصفح صالح |
| Presenton | `third_party/presenton` | `server/presenton/*` | FastAPI الأصلي بدأ محلياً واستجاب لـOpenAPI؛ لا توليد | مزوّد توليد وتصدير مهيأان خادمياً واختبار طرفي |
| Second Brain | `third_party/second-brain` | `server/secondbrain/*` | مستخرج المهام الأصلي يعمل عبر Python adapter | تهيئة خدماته الإضافية من المصدر دون نموذج بديل أو بيانات مصطنعة |

## 5. بوابات الإثبات

| البوابة | الأمر أو الدليل | وظيفة التدقيق |
|---|---|---|
| الأنواع | `pnpm check` | توافق عقود العميل والخادم |
| اختبارات الوحدة | `pnpm test` | منطق الملكية والجسور والتحقق من النصوص الثابتة |
| حدود المصادر | `pnpm verify:integration-boundary` | إثبات غياب OmniRoute من مراجع التشغيل |
| رحلة مساحة العمل | `pnpm verify:workspace-e2e` | إنشاء حساب ثم CRUD منظف للأقسام الأساسية |
| OpenCode | `pnpm verify:opencode` و`pnpm verify:opencode:session` | صحة Bun والجلسة وعدد النماذج المكتشفة |
| الواجهة | معاينة متصفّح مع جلسة محلية | فحص كل حالة مرئية، العربية/الإنجليزية، RTL/LTR، والمظهرين |

## 6. قواعد تنفيذ التدقيق

1. يبدأ كل قسم بالجرد: الصفحة، إجراءات المستخدم، نداءات tRPC، الكيانات، وحالات التحميل/الخطأ/الفراغ.
2. لا يُصلح أي عنصر إلا بعد تحديد سبب قابل لإعادة الإنتاج، ثم تُضاف أو تُحدّث تغطية اختبارية مناسبة.
3. لا تُصنع ردود وكيل أو سجلات نشاط أو نتائج توليد تجريبية لإخفاء غياب المحرك.
4. لا تعدّل اللقطات داخل `third_party`، ولا تزال ملفات وسائطها أو تنقلها دون موافقة صريحة.
5. لا يُوسم المحرك بأنه جاهز إلا باختبار ينفذ الطلب الحقيقي إلى المصدر ويثبت النتيجة وحدودها.
