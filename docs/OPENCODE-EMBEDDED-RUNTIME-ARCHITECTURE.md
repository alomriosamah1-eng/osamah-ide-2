# بنية تضمين OpenCode الحقيقي داخل Osamah IDE

## المصدر والنطاق

أُدرج مصدر OpenCode الرسمي غير المعدّل تحت `third_party/opencode` من الالتزام `ac1c048e6420eb4c728fd3e343a1ba7b076cba92`، مع الاحتفاظ بترخيص MIT المرفق معه. تحتوي النسخة 6,468 ملفاً وبلغ حجمها 144 ميغابايت بعد استبعاد بيانات Git فقط. لا يُستبدل المحرك بقائمة نماذج افتراضية أو عميل محاكاة؛ بل تبقى حزم المصدر الحقيقية هي المرجع لتنفيذ الجلسات والرسائل والأحداث والموافقات.

| الطبقة | المسار المملوك | المسؤولية |
|---|---|---|
| المصدر الخارجي غير المعدّل | `third_party/opencode/` | حزم OpenCode الأصلية، بما فيها المحرك وSDK والبروتوكول والخادم |
| غلاف Osamah | `server/opencode/` | بدء المحرك، فحص صحته، تمرير طلبات الجلسات، وحجب الأسرار عن المتصفح |
| الواجهة الحالية | `client/src/` | عرض حالة التشغيل والنماذج المكتشفة ومراسلات الجلسة فقط |

## نقطة التشغيل الفعلية

المحرك الحقيقي موجود في `packages/opencode`؛ وأمره الأصلي `serve` يستورد `Server.listen(opts)` ويبدأ خادم OpenCode عديم الواجهة. الخادم يركّب HTTP API وWebSocket ويتعامل مع الجلسات والأحداث، ولا يقتصر على حزمة SDK أو على واجهة الويب. يتطلب المصدر Bun، مع مدير الحزم المحدد في المصدر نفسه. أُضيف غلاف خادم Osamah في `server/opencode` يثبت مسار المصدر، يبني أمر التشغيل الحقيقي، ويكشف حالة قراءة فقط عبر tRPC من دون بدء عملية تلقائياً أو تمرير مفاتيح إلى المتصفح.

## ضوابط الدمج

ستبقى `third_party/opencode` بلا تعديلات مملوكة لـOsamah. أي تخصيص أو حجب صلاحيات أو تحويل مسارات سيكون في `server/opencode` فقط. لن يُحفظ مفتاح مزوّد أو كلمة مرور خادم في الواجهة أو في `localStorage`، كما لا تُعرض إلا النماذج التي يعيدها OpenCode أثناء التشغيل.

## حد التشغيل الحالي

بيئة التطوير الحالية تعمل بـNode/Vite ولا تحتوي Bun، ولذلك لا يصبح المصدر المضمّن خادماً عاملاً تلقائياً بمجرد نسخه. أُضيف `Dockerfile` مخصّص لـWebDev يوفّر Bun `1.3.14` وNode 22، يثبّت اعتماديات المصدر الأصلي، ثم يضبط `OPENCODE_EMBEDDED_AUTOSTART=1`. عند تشغيل الحاوية يبدأ خادم Osamah أولاً ثم يستدعي نقطة دخول OpenCode الأصلية `packages/opencode/src/index.ts serve` على `127.0.0.1` فقط. تبقى عملية بدء التشغيل صريحة عبر متغير البيئة ولا تستدعى من طلب متصفح.

## إثبات تشغيل المحرك

ثُبّتت اعتماديات OpenCode الأصلية باستخدام Bun `1.3.14` المتحقق من بصمته المنشورة (`951ee2aee855f08595aeec6225226a298d3fea83a3dcd6465c09cbccdf7e848f`). ثم شُغّل `pnpm verify:opencode` مع `OPENCODE_BUN_PATH` صريح. بدأ غلاف Osamah نقطة الدخول الأصلية، وردّ `http://127.0.0.1:4096/api/health` بنجاح، وأرجع الغلاف حالة `running` و`healthy` قبل إيقاف العملية بأمان. هذا تحقق لمحرك OpenCode الحقيقي المضمّن، لا لمحاكاة أو خادم خارجي.

نفّذ `pnpm verify:opencode:session` تحققاً ثانياً: بدأ المحرك الحقيقي، واستدعى `/api/model`، وأنشأ جلسة عبر `/api/session`. كانت نتيجة النماذج `0` لأن هذه البيئة لا تحتوي إعداد مزوّد OpenCode صالحاً؛ وهذا سلوك مقصود لا يُستبدل بقائمة افتراضية. تربط لوحة الدردشة الآن الحالة والنماذج والجلسات والموافقات عبر وسيط tRPC الخادمي فقط، فلا يرى المتصفح عناوين الحلقة المحلية أو مفاتيح المزوّد.
