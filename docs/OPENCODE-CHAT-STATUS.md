# حالة تشغيل OpenCode في دردشة الوكيل

**المرحلة:** اكتشاف نماذج حيّ من خادم OpenCode المحلي؛ ليست دردشة تنفيذية بعد.

## ما تعمل به الواجهة الآن

تظهر بطاقة **OpenCode runtime** وتحكم اتصال محلي أسفل مؤلف الدردشة في كل مساحة عمل. يدخل المستخدم أصل خادم OpenCode الذي يشغّله على جهازه، ثم تفحص الواجهة الصحة وتقرأ المزوّدات والنماذج الفعلية. لا تعني كلمة «محلي» نموذج LLM محلياً؛ بل تعني خادم OpenCode المحلي فقط.

| الحالة | دلالتها | سلوك الرسالة |
|---|---|---|
| `unconfigured` | لا خادم محفوظ أو لا نماذج OpenCode مفعّلة | تحفظ الواجهة الرسالة ولا ترسل طلباً |
| `checking` | فحص `health` واكتشاف المزوّدات والنماذج قيد التنفيذ | لا تدّعي جاهزية |
| `ready` | اكتُشفت نماذج مفعّلة من وقت التشغيل | يسمح بالاختيار، لكن التنفيذ ما زال معطلاً |
| `degraded` | العنوان أو بروتوكول الاستجابة يحتاج مراجعة | لا تنتج الواجهة ردّاً بديلاً |
| `offline` | خادم OpenCode غير قابل للوصول أو محجوب عبر CORS | لا تنتج الواجهة ردّاً بديلاً |

## ضمانات السلوك

1. كتالوج الاختيار يبدأ فارغاً، ويحمل كل عنصر معروض `source: "runtime"` فقط.
2. لا توجد قائمة fallback، ولا أسماء مزودين أو نماذج مفترضة، ولا افتراض لنموذج محلي أو لخدمة Claude/Anthropic.
3. تحفظ الواجهة عنوان الاتصال المحلي فقط؛ لا تحفظ مفاتيح النماذج أو كلمات المرور أو بيانات اعتماد في المتصفح.
4. لا ينشئ `sendMessage` رداً ذكياً مصطنعاً. حتى تكتمل طبقة الجلسات والموافقات، توضح الرسالة أنها لم تُرسل.
5. تحترم البطاقة والتحكم العربية والإنجليزية وRTL/LTR و`prefers-reduced-motion`.

## متطلب الاتصال

يجب أن يعمل OpenCode على جهاز المستخدم وأن يسمح لأصل الواجهة الحالي عبر CORS. عند نجاح الاكتشاف، تظهر فقط النماذج التي يعلنها OpenCode مفعّلة فعلياً.

## ما لم يُنفذ بعد

لا يزال إنشاء الجلسة، إرسال الرسالة، استقبال تدفق الأحداث، إيقاف المهمة، وتأكيد الصلاحيات خارج هذه المرحلة. لن يُعلن عن تنفيذ حيّ قبل اختبار تلك المسارات مع خادم OpenCode حقيقي.
