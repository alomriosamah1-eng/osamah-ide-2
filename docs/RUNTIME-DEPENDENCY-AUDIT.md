# جرد الاعتمادات وتشغيل المحركات

## نطاق المراجعة

راجعت الاعتمادات الإنتاجية المثبتة وحالة المحركات عبر عقود الخادم الفعلية، لا عبر مؤشرات الواجهة. لم يُثبَّت مزود محلي أو نموذج افتراضي أو بديل غير مصرح به؛ مصدر النماذج هو OpenCode المضمّن وحده.

| المحرك | دليل التشغيل | حالة الجسر في Osamah | النتيجة الصادقة |
|---|---|---|---|
| OpenCode | فحص الصحة نجح؛ اكتُشف **87** نموذجاً قابلاً للاختيار؛ سياسة التنفيذ الخادمية مشتركة بين الحالة وبوابة الجلسات. | `status=ready` و`agentReady=true`، مع تحقق خادمي من النموذج وجلسة مملوكة. | متاح للمستخدم المصادَق عليه. نجح فاحص الدور مرة في تلقي رد مساعد ضمن البرمجة والعروض والعقل الثاني، لكنه قد يتأخر مزود النموذج الحر؛ تُعرض المهلة كخطأ ولا يُختلق رد. |
| Theia | مصدره مضمّن، لكن تطبيق المتصفح غير مبني. | `status=build-required` و`agentReady=false`. | لا يبدأ التطبيق عملية IDE ولا يدّعي محرراً تشغيلياً قبل بناء Theia. عمليات المشاريع والملفات والمهام في Osamah تظل حقيقية ومستقلة. |
| Presenton | خدمة الصحة المحلية تستجيب على المنفذ `8787`. | `status=needs-configuration` و`agentReady=false`. | لا يعمل توليد/تصدير عروض حتى مزود معتمد وتمكين خادمي صريح؛ CRUD العرض والشرائح خادمي حقيقي. |
| Second Brain | مستخرج المهام Python المضمّن متاح عبر المهايئ الخادمي. | `status=available` و`agentReady=true`. | حفظ الملاحظات والبحث والروابط واستخراج/إنشاء المهام تعمل بالعقود الخادمية. |

## الاعتمادات

تأكدت قائمة الإنتاج المثبتة عبر مدير الحزم، وتشمل React وtRPC وReact Query وDrizzle/MySQL وZod وRadix وFramer Motion والحزم اللازمة لواجهة Osamah. لا توجد حزمة ناقصة تمنع تشغيل واجهة المشروع أو الجسر الحالي. تُدار تبعيات OpenCode وTheia وPresenton داخل لقطات المصدر المضمّنة ولا تُعدّل في هذه الجولة، التزاماً بحدود المورد الخارجية.

## اختبار السلوك

اجتاز `verify:workspace-e2e` دورة التسجيل المحلي والتفضيلات وCRUD المشاريع/الملفات/المهام والعروض/الشرائح ومكونات Second Brain مع تنظيف محتوى الاختبار. واجتازت اختبارات جسر OpenCode وسياسة التمكين والتحقق من النموذج. أضيفت آلية انتظار متوافقة: إذا أعاد إصدار OpenCode المضمّن الاستجابة الموثقة `503` لمسار `wait`، يستطلع الخادم رسائل الجلسة بمهلة صريحة ولا يعلن وصول رد قبل وجود رسالة مساعد فعلية.

> لا تعني صحة OpenCode أن كل طلب توليد مضمون زمنياً؛ توفر الرد يتبع المزود والنموذج المختار. عند المهلة تحتفظ الواجهة بالنص والجلسة ولا تضيف رسالة مساعد اصطناعية.

## مهلة الرد

يستخدم الجسر الخادمي مهلة انتظار افتراضية قدرها **90 ثانية** عند انتظار أول نص مساعد. يمكن للمشغل تعديلها عبر `OPENCODE_MESSAGE_WAIT_TIMEOUT_MS` ضمن المجال `5,000–300,000` مللي ثانية؛ القيم غير الرقمية أو الخارجة عن المجال لا تتجاوز الحدود الآمنة. قبول OpenCode للرسالة ثم غياب النص ضمن هذه المهلة يعيد حالة تنفيذ معلقة، وتستمر الواجهة في فحص الرسائل ضمن الجلسة نفسها بدلاً من إنشاء جلسة أو رد اصطناعي.
